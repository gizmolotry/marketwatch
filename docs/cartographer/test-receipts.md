# Executed-test receipts

The test-receipt overlay is separate from the static inventory. Scanning still executes nothing and still reports test declarations only. An operator must explicitly run `run-tests` with a verified inventory, the source checkout, the strict checked-in runner policy, and an external attestation key. Runner policy v2 adds `max_source_files` and `max_source_bytes`; v1 runner policies must be migrated and are rejected.

The runner accepts only inventoried test UIDs or bounded paths allowed by the policy. Before reading or copying a source file, it preflights the eligible file count and aggregate inventoried byte size against the policy. It then verifies the source bytes, copies eligible files into a temporary directory, verifies the copy, and invokes a fixed `[sys.executable, -m, pytest]` command with `shell=False` and `--rootdir=.`. Third-party plugin autoload and inherited `PYTEST_ADDOPTS` are disabled. A timeout terminates the whole isolated process tree.

The bundled plugin records structured native node IDs, native collection lines, normalized definition lines, original names, collection errors, and setup/call/teardown outcomes. A collected item joins exactly one inventoried declaration by repository path, definition line, and original name; its node ID must also be the declaration node ID or a parameterized case of it. Ambiguous, duplicate, shadowed, or dynamically rewritten identities cannot credit another declaration. Standard output, standard error, arbitrary environment values, and exception text are not retained. Event collection enforces the policy byte bound while events are produced. Overflow emits a small explicit non-promotable envelope instead of materializing or parsing an oversized event document.

Each `repo-cartographer-pytest-receipt/v2` receipt binds the source inventory root, snapshot, Git head/index, file root, scan config, the complete runner policy and its SHA-256, interpreter and pytest versions, structured argv, declaration keys and exact locations, selected source hashes, native cases and phases, exit status, and frozen-copy mutation result. `receipt_sha256` detects accidental payload corruption only. It is not an attestation and cannot authorize promotion.

Promotable v2 output requires an explicit HMAC-SHA256 signer. The signature covers the canonical receipt payload, integrity hash, algorithm, and stable `key_id`; secret key bytes are never written to the receipt, pytest argv, output, or logs. CLI callers provide a key file path or environment-variable name, never raw key material on argv. Verification requires the exact approved runner configuration and a trusted key resolver. A missing, unknown, wrong, or altered key/signature fails closed. Curated projection accepts receipts only with an explicitly supplied approved runner policy, records the consumed policy hashes in `test_runner_policy_sha256s`, and uses only verifier-authorized declarations.

Legacy `repo-cartographer-pytest-receipt/v1` remains available only through explicit integrity-only verification for migration and audit. Its self-hash may still be checked under the old structural rules, but it is always untrusted and non-promotable. Recomputing a v1 hash or a v2 `receipt_sha256` never creates external attestation.

## Promotion rule

Only an explicit required `test_capability` selector can consume receipts. A matched module-level test declaration scopes the join to every eligible non-fixture function/method declaration in that exact file; a direct function/method component scopes only that declaration. An empty derived declaration set is explicit and cannot promote. Every scoped declaration must have all collected parameter cases pass setup, call, and teardown plainly. Any unmapped dynamic node, skip, xfail, xpass, failure, error, missing phase, collection error, event-file overflow, timeout, nonzero suite exit, or frozen-copy mutation prevents promotion. A nonzero suite exit cancels every promotion from that receipt.

Receipt evidence changes only `verification`, from `test_declared` to `test_passed`. It cannot change definition, integration, artifact, learning, evaluation, runtime, approval, or effectiveness. Optional selectors never promote. A map with no receipts retains the original v1 serialization and declaration-only behavior.
